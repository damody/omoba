# Design

Typed Purchase/Sale ledger records share sequences, eight-record bound, source generation, deduplication, shape/admission and commitment. Paid is the captured nonnegative amount: purchase refunds it, sale subtracts it. Sale requires an empty original slot and valid original cooldown bits; restore exactly those bits, never reset a spent cooldown. Reject insufficient funds atomically with existing error/result and balance reason, described by native UI. Hash domain v2 commits operation kind and result slot; no wire layout change. Sale invalidates every older record before adding its own, so undo cannot reopen old benefited purchases. A later purchase may cover a sale via existing newest-first unwind, preserving monotone eligibility. Sale records invalidate on combat/movement/item use/death using shared benefit mask. Dead roster sale records bind to the new life using the existing authority path.
