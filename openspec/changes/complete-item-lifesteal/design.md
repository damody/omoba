# Design

Normalized lifesteal defaults to zero and omits legacy JSON fields at zero. Model validation rejects nonfinite/negative/over-one/subquantum values. Rust generated catalog and runtime ItemBonus retain the same value; inventory totals add and clamp to100% at the shared passive boundary. One canonical permanent BuffStore lease is replaced only on existing dirty rebuild and new-life finalization; zero removes it. Existing shared leech arithmetic/target/source-life policies remain authoritative. No item/hero/camp identity branches.

Authored catalog15 is a900gold10attack12.5%lifesteal component; catalog16 is1800gold25attack25%lifesteal, using component15 plus sword1. Existing prices/recipes unchanged. Unreal generated metadata adds a typed passive rate and shared description validates/prints percentage and physical-health-loss exclusions. Use the existing actual passive card tooltip workflow to capture the new equipment text. Preserve old64 historical images and prior fresh R image with hashes; add one freshly inspected item image.

Freeze after owned codegen retirement, run fresh Rust/backend/UE/native acceptance once, then source proof/archive closure with original exit identities and API reaps. Extend existing tests where meaningful; no true network match or historical frontend work.
