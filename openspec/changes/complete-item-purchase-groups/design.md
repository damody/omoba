# Design

Optional purchase_group contains id, display name and limit1..6; omitted legacy JSON stays stable. Catalog members of one group must agree on name/limit. Common atomic buy kernel removes actual recipe components, inserts candidate, validates resulting owned group counts, then commits wallet/inventory. Preview/bots inherit this kernel. No item-specific branches. Undo validates restored inventory against current group policy before any refund/restoration. Group conflicts in undo use existing unavailable/shape reason. New ordinary buy result16 is PurchaseGroupLimit; existing0..13 remain,14/15 remain undo-only. Normal receipt codec explicitly allows16 for buy rejection only, keeping wire length/version; bridge reuses this strict codec. Native shared metadata/tooltip shows group and maximum, normal feedback explains result16.

Boots and upgrade share group footwear/limit1. Prior formal unique-passive test changes to real current catalog semantics (duplicate rejection, one retained item, no fallback boot after sale); arbitrary passive stacking/whole-winner tests remain unweakened. New formal test covers actual result and owner-only rejected receipt, recipe atomicity, sale/rebuy/undo/new life and replay. Test malformed/inconsistent custom catalogs, limits above1, independent groups, full-inventory upgrade and undo restoration conflicts. Fixed Lua/Rust/UE, preserve original failures and identity-bound exits.
