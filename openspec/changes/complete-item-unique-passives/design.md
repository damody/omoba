# Design

An optional unique_passive owns a validated group, display name, positive priority and bounded atk/hp/ms/armor/lifesteal/critical_chance. Base item attributes continue to stack. Per group select highest priority, then lexicographically smallest item id, independently of inventory slot/hash iteration. Identical copies contribute once. Apply the entire winning passive, never per-stat cherry picking. Different groups stack. Rebuild through existing inventory dirty/new-life paths without healing. Purchase undo benefit masks compare actual aggregate before/after, so suppressed passives grant no phantom benefit and upgrades retain their real benefit. Existing boot25ms becomes group movement tier1; new900gold upgraded boots consume boots and grant45ms tier2. No hero/item-name runtime branches.

Shared model validation, generated Rust/Unreal metadata and native tooltip explain group/rank/nonstacking. Meaningful tests cover slot permutations, tie policy, multi-stat winner, independent groups, malformed custom catalogs, recipe/sale/undo/new-life and no heal. Preserve parent sources and generated candidates before edits, owned codegen before source freeze, then fresh Rust/backend/UE/native validation and actual image review.
