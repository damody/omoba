# Package schema v3

狀態：**v3.3**（2026-10-29；v3.0 於 M0 凍結，v3.1～v3.3 是向後相容的追加，見 §12.10～§12.12 與 §13）。之後只做向後相容的擴充；不相容的修改要附遷移腳本（計畫 README §3.2 第 5 點）。

v3 把一招技能、一個道具寫成**資料**：數值（values）、說明模板（text）、行為（behavior）、出處（provenance／quirks）。建置期由 Lua 驗證、編譯成 IR；遊戲執行期沒有 Lua（計畫 D8）。行為模型的設計理由見 [behavior-model-v1.md](../../plans/2026-10-28-history-nobu-full-port/behavior-model-v1.md)，數值單一來源見 [value-single-source.md](../../plans/2026-10-28-history-nobu-full-port/value-single-source.md)。

## 1. 文件

一份 v3 文件是一個 Lua 檔，和 v1／v2 一樣回傳 `function(ctx)`：

```lua
return function(ctx)
  return {
    schema_version = 3,
    kind = "hero",            -- hero：一位英雄的技能組；items：一組道具
    id = "C01",               -- 文件 id（英雄用原作英雄 id，道具組自取）
    source = { repository = "history_nobu", commit = "f966720", root = "game/dota_addons/nobu/scripts/" },
    hero = { source_id = "C01", text = { zh_TW = { name = "明智光秀" }, en = { name = "Akechi Mitsuhide" } } },
    values = { ... },         -- 文件共用數值（少用；通常放在技能裡）
    unit_state = { ... },     -- 英雄層級的有型別變數（§6）
    abilities = { ... },      -- §3
    items = { ... },          -- §3.6
    statuses = { ... },       -- 不屬於任何技能的共用狀態（§4）
    unit_templates = { ... }, -- §7
    routines = { ... },       -- §5.6
    hooks = { ... },          -- §8
  }
end
```

放置位置：

- 英雄：`docs/character_pipeline/packages/<package>/v3.lua`，每位英雄一份，不論是否上架。資料夾以英雄英文名的 snake_case 命名（長音符號去掉，例如 `nohime`、`fuma_kotaro`）。已上架英雄的 package 另有 v2 檔（`character.lua`、`abilities.lua`……，M5 前保留），`validate_package.lua` 兩者都檢查；未上架英雄的資料夾只有 `v3.lua`。
- 道具：`docs/character_pipeline/items/*.lua`（`kind = "items"`），每件商店道具只出現在一份文件。上架與否由商店（`templates/moba_items.lua`）決定，`gen_item_v3.lua` 只處理上架的道具。
- 工具一律經 `docs/character_pipeline/tools/v3_sources.lua` 找文件。`census-v3/` 只剩 README（普查紀錄）。

驗證：

```bat
tools\lua\lua.exe docs\character_pipeline\tools\package_v3.lua <檔案或 package 目錄> ...
tools\lua\lua.exe docs\character_pipeline\tools\validate_package.lua <檔案或 package 目錄>
tools\lua\lua.exe scripts\tests\package_v3_test.lua
```

### 1.1 id

- 所有 id（技能、道具、狀態、單位模板、routine、hook）在同一份文件內唯一，snake_case ASCII。
- 技能 id 用 `<英雄小寫>_<英文名>`，例如 `c01_ground_flame`；`source_id` 記原作 id（`C01E`）。
- 狀態 id 用 `<原作技能小寫>_<用途>`，例如 `c01e_stun`。
- 道具 id 沿用原作（`item_brave_ring`）。

## 2. values（數值）

每個玩法數值**只定義一次**，放在擁有它的技能、道具、狀態或單位模板的 `values` 表。其他地方一律用名稱引用：行為寫 `$名稱`，說明寫 `{名稱}`。

```lua
values = {
  cooldown  = { 14, 13, 12, 11, unit = "s", source = "kv:AbilityCooldown" },
  radius    = { 300, unit = "dist", source = "kv:C01E_Radius" },
  damage    = { 200, 300, 400, 500, unit = "dmg", damage_type = "magical", source = "kv:C01E_Damage" },
  stun      = { 0.5, 1, 1.5, 2, unit = "s", kv = { 1, 1.5, 2, 2.5 },
                source = "script:vscripts/heroes/C_Neutral/C01_Mitsuhide_Akechi.lua:107-111 level*0.5",
                source_differs = "KV C01E_Duration 沒有被使用" },
  chance    = { "1900/101", unit = "pct", source = "script:...:487 RandomInt(0,100) <= 18" },
  interval  = { 0.4, unit = "s", hidden = true, source = "script:..." },
  max_total = { expr = "$damage + $wave_count * $wave_damage", unit = "dmg" },
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `[1..n]` | 與 `expr` 擇一 | 逐 rank 的值。個數是 1（所有 rank 相同）或 `max_level`。`per = "hero_level"` 時是 1 或 25。可以是數字，或十進位、分數字串（`"1900/101"`，`pct` 是百分比數字，所以約 18.81% 寫 1900/101）；建置期由字串直接轉 Fixed64，不經過浮點 |
| `expr` | 與數值擇一 | 衍生值：運算式（§5），建置期逐 rank 求值；不能循環引用 |
| `unit` | 是 | 見詞彙表。`count` 必須是整數 |
| `source` | 數值必填 | `<前綴>:<出處>`：`kv:`、`script:`、`text:`、`rules:`、`design:`、`assumed:`。`expr` 可省略或寫 `derived` |
| `kv`、`source_differs` | — | 原作 KV（或說明）有不同的數值而沒有採用時，`kv` 記那個數值，`source_differs` 必須說明理由 |
| `hidden` | — | `true`：玩家看不到的內部數值（間隔、內部倍率、呈現參數）。不能出現在說明裡 |
| `damage_type` | — | 傷害數值的類型，說明與網站依此上色 |
| `per` | — | `rank`（預設）或 `hero_level` |
| `integer` | — | 非 `count` 但必須是整數 |
| `note` | — | 備註 |

### 2.1 rank 與作用域

- `$x` 取擁有者**目前的 rank**：技能是技能等級；道具是 1（或道具的 `max_level`）；狀態跟著施加它的技能；單位模板跟著建立它的技能（模板設 `max_level` 時）。
- 名稱解析由內往外：狀態自己的 `values` → 所屬技能或道具 → 文件 `values`。
- 引用其他擁有者：`$<id>.<名稱>`，例如 `$c01_ground_flame.radius`（routine 必須這樣寫）。
- `pct` 單位在**運算式裡是比例**：`move_speed_pct = { 25, unit = "pct" }` 在行為裡讀到 0.25，說明顯示「25%」。單位屬性的 `magic_resist`、`base_magic_resist`、`hp_pct` 等也是比例。所以行為裡不會出現 `/ 100`。

### 2.2 資訊列

冷卻、耗魔、耗血、施法距離、範圍、前搖、引導時間、次數、需要等級、道具價格與屬性加成，由技能的標頭欄位（`target.range`、`target.aoe_radius`、`cast.*`、`cost.*`、`requires.hero_level`、`shop.*`、道具 `passive.stats`、單位模板的屬性）自動產生固定格式的資訊列，**不寫在說明文字裡**。被這些欄位引用的數值算「玩家看得到」。

## 3. 技能（ability）

```lua
{ id = "c01_ground_flame", source_id = "C01E", slot = "W", kind = "active", max_level = 4, tags = { "basic" },
  values = { ... }, text = { ... },
  target = { type = "point", range = "$cast_range", aoe_radius = "$radius" },
  cast = { cast_point = "$cast_point" },
  cost = { mana = "$mana_cost", cooldown = "$cooldown", cooldown_start = "on_cast" },
  requires = { hero_level = "$required_level" },
  flags = { "pierce_magic_immune" },
  statuses = { ... },                 -- 這招擁有的狀態（§4）
  events = { on_cast = { ... } },     -- 事件 → action（§5）
  passive = { ... },                  -- 被動：隱含一個永久狀態（§3.3）
  unit_state = { ... },               -- 這招的有型別變數（§6）
  coverage = "expressible", confidence = "high", pending = { ... },
  quirks = { ... }, provenance = { ... } }
```

| 欄位 | 說明 |
|---|---|
| `slot` | `Q W E R D F`：英雄技能欄，同一位英雄不能重複。`sub`：子技能、換出的技能；`hidden`：給單位模板或內部用 |
| `kind` | `active`、`passive`、`toggle`、`autocast`、`channel` |
| `tags` | `ultimate`、`basic`、`toggle`、`channel`、`orb`……規則與其他技能以 tag 判斷，不以名稱判斷（v1 §3） |
| `max_level` | 1..25 |
| `learnable`、`level_link` | `learnable = false` 加 `level_link = "<另一招>"`：子技能跟著主技能的等級 |
| `target` | `type`（`none unit point direction vector unit_or_point tree item`）、`range`、`aoe_radius`、`min_range`、`vector_length`、`team`、`types`、`flags`。只決定施放合法性與指示器 |
| `cast` | `cast_point`、`backswing`、`channel_time`、`immediate`（不打斷目前動作）、`interruptible`、`move_while_casting`、`turn_while_casting`、`ignore_backswing` |
| `cost` | `mana`、`health`、`gold`、`cooldown`、`cooldown_start`、`charges { max, restore, initial }`、`cooldown_groups { { group, length } }`、`refund` |
| `requires` | `hero_level`、`has_status`、`not_status`、`condition`（不成立就不能施放） |
| `flags` | `pierce_magic_immune` 等，見詞彙表 |

### 3.1 事件

`events` 是「事件名稱 → action 陣列」，或 `{ actions = {...}, filter = 條件, interval = 運算式 }`。技能事件見詞彙表（`on_phase_start`、`on_cast`、`on_channel_tick`、`on_channel_end`、`on_toggle_on`、`on_order_targeted`、`on_equip`……）。

可用的名稱（§5.4）依 `target.type` 而定：`unit`、`unit_or_point`、`tree`、`item` 有 `target`；`point`、`unit_or_point`、`direction`、`vector` 有 `point`；`direction`、`vector` 有 `direction`；`vector` 另有 `vector_end`。

### 3.2 限時換技能、子技能、重施放

- 子技能：`slot = "sub"`，`learnable = false`，`level_link` 指向主技能；用 `swap_abilities { from, to, duration, cooldown_policy }` 換上。原技能冷卻 `freeze`、`continue` 或 `reset`。
- 重施放窗口：主技能 `on_cast` 套一個狀態並換上子技能；子技能的 `requires.has_status` 指向那個狀態；狀態 `charges` 或 `on_expired` 換回來。
- 施法前攔截：狀態的 `on_order_targeted` 觸發可以 `cancel_cast`。

### 3.3 被動

`passive = { stats, states, triggers, aura, unique_group, reveal }` 等於學會後在持有者身上掛一個永久、不可驅散的隱含狀態；`triggers` 裡的 `self` 是持有者。被動技能的行為只寫在 `passive.triggers`；`events` 只能有 `on_learn`、`on_upgrade`。

### 3.4 coverage（每一筆的狀態）

| 值 | 意思 | 驗證器的要求 |
|---|---|---|
| `expressible` | 全部用資料表達 | 不能有 hook action，不能有 `pending` |
| `needs_hook` | 有資料表達不了的部分，用 hook | 至少一個 hook action（直接或經 routine）；不能有 `pending` |
| `pending` | 有待確認的事（原作行為不明、詞彙不夠、等使用者決定） | `pending = { { what, why, gap? } }` 至少一筆 |

`confidence`：`high`、`medium`、`low`，表示普查者對「這份資料等於原作實際行為」的把握。

### 3.5 出處與 quirks

- `provenance`：原作檔案與行號，路徑相對於 `source.root`，格式 `<path>:<行號或區間>`，至少一筆。
- `quirks`：原作的怪異行為與 bug，每筆 `{ text, policy, ref? }`。`policy` 依計畫 D13：

| policy | 意思 |
|---|---|
| `as_source` | 照原作實際行為（預設） |
| `fix_candidate` | 明顯違反設計意圖且影響可玩性；列入修正候選清單由使用者決定，資料目前仍照原作 |
| `design_intent` | 跟 tick 頻率等引擎副作用有關，照設計意圖 |
| `no_effect` | 原作報錯或死碼，照中斷後的結果（通常沒有效果） |
| `note` | 只是紀錄，不影響結算 |

原作說明文字的原文不放在 v3 文件；需要時放在 package 的 `source.lua`（v2）並由出處比對工具處理。

### 3.6 道具

```lua
{ id = "item_ghost_mask", source_id = "item_ghost_mask",
  values = { cost = { 2000, unit = "gold", source = "..." }, recipe_cost = {...}, all_stats = {...}, ... },
  text = { zh_TW = { name = "鬼面", body = "..." }, en = { ... } },
  shop = { cost = "$cost", recipe = { components = { "item_strength_ingot", ... }, recipe_cost = "$recipe_cost" },
           sellable = true, droppable = true, consumable = { charges = "$charges" } },
  passive = { stats = { str = "$all_stats", ... }, unique_group = "...", triggers = { ... } },
  active = { kind = "active", target = {...}, cast = {...}, cost = {...}, events = {...} },
  statuses = { ... }, coverage = ..., confidence = ..., quirks = ..., provenance = ... }
```

- 道具 `body` 可以省略（只有屬性的零件）。
- `passive.stats` 會自動產生「+20 攻擊力」這類行，算資訊列。
- 裝備與卸下：`passive` 的隱含狀態在裝備時建立、卸下時移除，所以用 `on_created`、`on_removed`；`active.events` 也可以用 `on_equip`、`on_unequip`。
- 道具文件裡的技能只能是 `hidden` 或 `sub`（給召喚物或子技能）。

## 4. 狀態（status）

```lua
{ id = "c01e_stun", duration = "$stun", stacking = "independent", dispel = "basic", visibility = "debuff",
  reveal = "public", status_resistance = "normal", scope = "unit",
  stats = { move_speed_pct = "$slow", armor = { op = "add", value = "-$armor_cut", when = "self.is_hero" } },
  states = { "stun" },
  vars = { absorbed = { type = "fixed", init = "0", reveal = "team" } },
  absorb = { amount = "$shield", types = { "physical" }, on_broken = { ... } },
  charges = "$blocks", immune_to = { "stun" }, block_reapply = true, unique_group = "evasion",
  aura = { radius = "$radius", team = "ally", status = "x_aura_buff", linger = "$linger", include_self = true },
  triggers = { on_created = { ... }, periodic = { interval = "$tick", actions = { ... } }, on_attack_hit = { ... } },
  forced_move = { toward = "landmark(team_of(self), base)", locks = { ... } },
  remove_on = { "death" }, cue = "c01r_weapon_glow", text = { zh_TW = { name = "..." }, en = { name = "..." } } }
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `duration` | 是 | 運算式或 `"infinite"`。`apply_status { duration = ... }` 可以覆寫 |
| `stacking` | 是 | `refresh`、`extend`、`independent`（多實例）、`keep`、`replace`；或 `{ max, mode, value_stacks, per_stack_duration, decay, initial }` |
| `dispel` | 是 | `none`、`basic`、`strong`、`death_only` |
| `visibility` | 是 | `buff`、`debuff`、`hidden` |
| `reveal` | 是 | 揭露政策（計畫 §3.2 第 1 點）：`public` 雙方 replica 都知道；`team` 只有己方；`derived` 只揭露結算結果。**會影響對方 replica 決策的判定只能讀雙方都有的狀態** |
| `stats` | — | StatKey → 運算式，或 `{ op, value, when, per_stack }`。`op`：`add`（預設）、`pct`、`mul`、`set_absolute`、`min`、`max` |
| `states` | — | 控制與狀態旗標（`stun`、`root`、`magic_immune`、`invisible`……） |
| `vars` | — | 狀態實例上的有型別變數，行為以 `vars.x` 讀、`set_var` 寫 |
| `stacking.value_stacks` | — | `true`：`stats` 的 `per_stack = true` 項目乘上層數。原作 datadriven 常常「層數只是顯示」，那時用 `false`（預設） |
| `absorb` | — | 吸收護盾：量、可吸收的傷害類型、`lethal_only`、`fraction`、吸收與破盾時的 action |
| `charges` | — | 次數用完就移除（格擋 N 次） |
| `immune_to`、`block_reapply` | — | 免疫的狀態、旗標或 tag；阻擋同一個狀態再套用 |
| `unique_group` | — | 同組逐屬性取最高（光環跨來源、閃避只取最高） |
| `aura` | — | 光環：半徑、隊伍、給的狀態、殘留時間 |
| `triggers` | — | 狀態觸發（§5.3）。同一事件要多個時加數字尾碼：`periodic_2` |
| `scope` | — | `unit`、`hero`（持有者英雄層級，賣掉、死亡仍保留）、`item_instance`、`permanent` |
| `forced_move` | — | 強制朝某處走，`locks` 列出被鎖的指令 |
| `remove_on` | — | `death`、`owner_death`、`unequip`、`channel_end`、`attack`、`cast`、`move` |
| `cue` | — | 呈現 id；只為了凍住動畫的效果放在 cue，不放在 `states` |
| `text` | — | 狀態圖示的名稱與說明（選用；有就要兩種語言） |

狀態觸發裡可用：`self`（持有者）、`caster`（施加者）、`source`（同 `caster`）、`status`（`stacks`、`remaining`……）、`vars`，以及事件的 `event.*`。

## 5. 行為

### 5.1 action

行為是 action 陣列。每個 action 是 `{ op = "<名稱>", <參數> = ... }`：

```lua
{ op = "damage", to = "it", type = "magical", amount = "$damage", require_source_alive = true }
{ op = "apply_status", status = "c01e_stun", to = "it", duration = "$stun" }
{ op = "for_each", select = { from = "point", shape = "circle", radius = "$radius", team = "enemy", types = { "hero", "creep" } },
  actions = { ... } }
```

- 全部的 action 與參數見詞彙表。`!` 是必填；不認得的參數是錯誤（防止打錯字）。
- 參數型別：
  - `expr`、`cond`、`unit`、`point`、`vec`、`any`：運算式字串（§5.5）；
  - `actions`：巢狀 action 陣列；`selector`：§5.2；
  - `status`、`ability`、`template`、`routine`、`hook`：已宣告的 id（`ability` 也可以是運算式，例如 `event.ability`）；
  - `cue`：呈現 id（任意字串）；`name`：snake_case 綁定名稱；`bool`：Lua 的 true／false；`enum:a|b`；`list:型別`；`table`：名稱 → 運算式。
- **結果綁定**：有 `as` 的 action（`create_unit`、`projectile`、`zone`、`damage`、`take_gold`、`random_pick`……）把結果綁到名稱，後面的 action 可以使用；`let { name, value }` 綁定運算式的值。
- **控制流**：
  - `if { cond, actions, otherwise }`；
  - `for_each { select, as = "it", actions }`；
  - `repeat { count, interval, first, while, stop_when, as, actions }`：至少要有 `count`、`while` 或 `stop_when` 其中之一；
  - `delay { time, id, capture, actions }`：`capture` 列出要捕捉當下值的名稱，`cancel_delay { id }` 可以取消；
  - `chance { p, pity_after, counter, actions, otherwise }`：決定性偽隨機。`pity_after = N` 表示連續 N 次失敗後下一次必中；`counter` 決定計數器的共用範圍（`ability`、`hero`、`item_name`、`status`），計數進 hash；
  - `random_pick { options = { { weight, value?, actions? } }, as }`；
  - `call { routine, args }`、`hook { name, args, as }`、`stop`。
- **規則層**負責的事，技能資料不能重做（v1 §1）：魔法傷害對魔免歸零、攻擊者死亡不造成傷害（`require_source_alive` 預設依原作為 true）、狀態抗性、緩速合成、減療取最強、魔抗池、法術增幅。
- **`damage` 的來源與法術增幅**（E188，工作線 B 的規則層以這條為準）：
  - 預設（不寫 `require_source_alive`）等於原作的 `AMHC:Damage`／`unit:Damage`：攻擊者必須存活，而且不吃法術增幅（amhc.lua 呼叫 ApplyDamage 時不帶 ability）。
  - `require_source_alive = false` 等於原作的 KV `Damage` 動作或 `ApplyDamage`：不檢查攻擊者存活，帶 ability 才吃法術增幅。
  - 原作的 `ApplyDamage` 沒帶 ability（例如 B08E 燒魔），或攻擊者是 dummy 單位時，要加 `flags = { "no_amplify" }`。
  - 只為了「不檢查攻擊者存活」而寫 false 是錯的：那會同時讓這次傷害吃法術增幅。要依原作的寫法決定。
  - 2026-10-29 的普查逐處對過原作，結果見 [spell-amp-census.md](../../plans/2026-10-28-history-nobu-full-port/spell-amp-census.md)。
- 結構常數：行為裡只能出現 `0`、`1`、`-1`；其他數字一律寫進 `values` 並用 `$名稱`（必要時標 `hidden`）。Lua 的數字字面值與運算式裡的數字都檢查。
- 巢狀 action 自動綁定的名稱：`for_each` 的 `as`（預設 `it`）；`repeat` 的 `as`（次數，從 0 起）；`projectile`／`dash` 的 `on_hit`、`zone` 的 `on_enter`／`on_leave`、`create_pickup` 的 `on_pickup` 綁 `it`；`projectile` 的回呼另有 `here`（投射物位置）；這些 action 的 `as` 在自己的回呼裡也可以用。

### 5.2 selector

```lua
{ from = "caster", shape = "circle", radius = "$radius", team = "enemy", types = { "hero", "creep" },
  flags = { "include_magic_immune" }, where = "not it.is_building", order = "nearest", prefer = "has_status(it, c07e_bind)",
  limit = "$max_targets", post_filter = "not it.is_magic_immune" }
```

- `from`：起點單位或位置。形狀與必填參數：`circle(radius)`、`ring(inner, outer)`、`cone(angle, length)`、`line(length, width)`、`rect(length, width)`、`segment(to, width)`、`global`、`unit`（只有 `from` 本身）。
- `team` 必填；`types`、`exclude_types`、`flags` 見詞彙表。
- 預設和 Dota 不帶旗標的 `FindUnitsInRadius` 一樣：**包含**隱形單位與戰爭迷霧裡的單位；**排除**魔免、無敵、不在場上、不可選取、已死亡的單位。`visible_only`（原作 FOW_VISIBLE）只選施法者隊伍看得到的；`exclude_invisible`（原作 NO_INVIS）排除隱形；`include_magic_immune` 等納入預設排除的單位。
- `relative_to`：`order = nearest／farthest` 的基準點（預設是 `from`）；`visible_to`：只選這個單位的隊伍看得到的；`exclude`：排除這個單位。
- `where`、`prefer`、`post_filter` 是條件，`it` 是候選單位。`limit` 在 `post_filter` **之前**計算，所以可以照實表達「魔免者佔名額但不受影響」。
- 排序預設依 entity id，保證決定性。

### 5.3 狀態觸發與事件參數

狀態與被動的 `triggers` 是「事件 → action 陣列」或 `{ actions, filter, interval, first, who, phase, priority }`：

- `periodic`、`on_channel_tick` 必須有 `interval`。
- `filter` 是條件，不成立就不執行。
- `who`：`on_ability_executed` 這類事件看誰（`self`、`any_enemy`、`any_ally`、`any`、`owner`）。
- 事件參數寫 `event.<參數>`，每個事件有哪些參數見詞彙表；`event.attack.*`、`event.damage.*`、`event.order.*` 是紀錄，欄位也在詞彙表。
- 傷害事件分減免前（`on_take_damage_pre`、`on_deal_damage_pre`，可以 `modify_damage`）與減免後（`on_take_damage`、`on_deal_damage`）。`event.damage.raw`、`after_armor`、`final` 分別是減免前、護甲後、最終值。吸血類一律用 `final`。
- 攻擊管線（v1 §2）：`on_attack_windup`（前搖開始；爆擊在這裡擲骰並 `modify_attack`）→ `on_attack_launch`（出手；法球扣魔）→ `on_attack_hit` 或 `on_attack_miss`；`on_attack_cancel`；被攻擊方 `on_attacked`。

### 5.4 名稱

運算式中可用的名稱：

| 名稱 | 何時可用 | 型別 |
|---|---|---|
| `caster` | 永遠：技能或道具的持有者；狀態裡是施加者 | unit |
| `caster_hero` | 永遠：召喚物的主人英雄（英雄自己就是自己） | unit |
| `ability` | 永遠：目前這招 | ability |
| `game` | 永遠：`game.time`、`game.is_night`…… | game |
| `rules` | 永遠：`rules.<a>.<b>`，對應 `scripts/lua_data/templates/game_rules.lua`；M2 尚未加入的鍵暫列在 `v3_vocab.lua` 的 `RULES_PENDING` | num |
| `state` | 永遠：`state.<變數>`，§6 宣告的變數 | 依宣告 |
| `target`、`point`、`direction`、`vector_end` | 技能事件，依 `target.type`（§3.1） | unit／point／vec |
| `self`、`source`、`status`、`vars` | 狀態觸發與被動 | unit／unit／status／依宣告 |
| `event` | 有參數的事件 | — |
| `it`、`here`、`as` 綁定、`let`、routine 參數 | 見 §5.1 | 依來源 |

單位、技能、狀態、道具、位置的屬性名稱見詞彙表；屬性可以串接，例如 `caster.owner.level`、`event.attack.target.hp`。

### 5.5 運算式文法

數值、條件、單位與位置引用共用一份語言。

```text
expr    := or
or      := and { "or" and }
and     := not { "and" not }
not     := "not" not | cmp
cmp     := sum [ ( "==" | "~=" | "!=" | "<" | "<=" | ">" | ">=" ) sum ]
sum     := prod { ( "+" | "-" ) prod }
prod    := unary { ( "*" | "/" | "%" ) unary }
unary   := "-" unary | postfix
postfix := primary { "." NAME }
primary := NUMBER | "true" | "false" | VALUE | NAME "(" [ expr { "," expr } ] ")" | NAME | "(" expr ")"
VALUE   := "$" NAME [ "." NAME ]           -- $damage；$c01_ground_flame.radius
NAME    := [A-Za-z_][A-Za-z0-9_]*
NUMBER  := DIGITS [ "." DIGITS ]           -- 只允許 0、1（與 -1）
```

- 優先序由低到高：`or` < `and` < `not` < 比較 < `+ -` < `* / %` < 單元負號 < 欄位存取。比較不能連寫。
- 型別：`num`、`bool`、`unit`、`point`、`vec`、`ability`、`status`、`team`。條件位置（`cond`、`if`、`where`、`filter`）必須是 `bool`；`and`、`or`、`not` 只接受 `bool`；`+ -` 可以用在位置與向量。單位可以當成位置用。
- 函式與參數型別見詞彙表。參數型別是 `status`、`template`、`tag`、`name` 的位置要寫**名稱**（不加引號）：`has_status(it, c07e_bind)`、`has_tag(it, building)`、`landmark(team_of(self), base)`。驗證器會確認名稱已宣告。
- 沒有字串字面值；沒有指定運算。
- 點位產生器：`random_point(center, min, max)`（環形內的決定性亂數點）、`circle_point(center, radius, n, i)`（圓周 n 等分的第 i 點）、`polar(center, angle_deg, distance)`、`offset(p, dir, distance)`、`lerp_point(a, b, t)`。

### 5.6 routine

同一位英雄多招共用的一段 action，例如 C01 兩種地焰波次、F 強制觸發 R：

```lua
routines = {
  c01e_wave = { params = { center = "point", amount = "num", stun = "num" }, actions = { ... } },
}
-- 使用：{ op = "call", routine = "c01e_wave", args = { center = "at", amount = "$damage", stun = "$stun" } }
```

routine 裡的數值必須寫 `$<擁有者>.<名稱>`；可用的名稱只有永遠可用的名稱與參數。`call` 的 `args` 必須剛好對應 `params`。

## 6. unit state 與 vars

```lua
unit_state = {
  c01r_noncrit = { type = "int", init = "0", reveal = "team", scope = "hero" },
}
```

- `type`：`int`、`fixed`、`bool`、`unit`、`point`、`vec`、`tick`、`unit_list`、`ability`、`item`。
- `reveal` 必填（揭露政策）；`scope`：`hero`（跨死亡保留）、`ability`、`unit`、`item_instance`、`item_name`、`permanent`。
- 文件層、技能層、道具層都可以宣告；以 `state.x` 讀、`set_state { var, value, on }` 寫。全部進 parity hash。
- 單位、樹、道具、投射物等引用帶世代號，用 `alive(x)`／`exists(x)` 檢查。
- 狀態實例變數宣告在狀態的 `vars`，格式相同；`set_var { var, value }`，在別的狀態上要加 `status` 與 `on`。

## 8. hook

資料表達不了的部分才寫 Rust hook（計畫 D7）：

```lua
hooks = {
  b11_bow_infinite_range = {
    why = "改良和弓對指定目標無限射程，並依攻擊時序計次；現有攻擊管線沒有「對單一目標改射程」的概念",
    test = "b11_bow_infinite_range_conformance",
    kind = "action", params = { target = "unit" }, reads = { "$b11_bow.max_shots" },
  },
}
-- 使用：{ op = "hook", name = "b11_bow_infinite_range", args = { target = "event.target" } }
-- 或在運算式中：hook_value(b11_bow_infinite_range, it)
```

- `why` 至少十個字，說明為什麼資料表達不了。`test` 是對應的 conformance 測試名稱（v1 §10）。
- `reads` 列出 hook 讀的數值（`$擁有者.名稱`），算「有人用」。hook 不能在 Rust 裡抄數字（value-single-source §5，M3 的 lint）。
- 用到 hook 的技能或道具，`coverage` 必須是 `needs_hook`。宣告了沒用的 hook 是錯誤。

## 9. text（說明模板）

```lua
text = {
  zh_TW = { name = "地焰召來", body = "{delay} 秒後……造成 {damage} 魔法傷害並暈眩 {stun} 秒……若有{@c01_blood_flame}層數……" },
  en    = { name = "Ground Flame Summoning", body = "After {delay} seconds ... {damage} magic damage ... {@c01_blood_flame} ..." },
}
```

- 語言：`zh_TW` 與 `en` 都必填（計畫 D11）。欄位：`name`（必填）、`body`（技能必填）、`short`、`lore`、`status_name`、`status_body`。
- 佔位符：
  - `{名稱}`：本擁有者（或外層）的數值；`{名稱:格式}`，格式見詞彙表（`all`、`current`、`signed`、`abs`、`int`、`max`）；
  - `{擁有者.名稱}`：其他擁有者的數值；
  - `{rules.a.b}`：規則層數值；
  - `{@id}`：另一招、狀態、道具或單位模板的名稱（同語言），名稱因此也只寫一次。
- **說明文字裡不能有數字**（半形與全形）。數量「一」用中文字或英文字（「消耗一層」、「one charge」）。
- 兩種語言的佔位符集合必須相同（格式可以不同）。
- `hidden` 的數值不能出現在說明裡。
- 冷卻、耗魔、射程等資訊列的數值不必寫進說明（§2.2）。

| 行為 | action 與參數存在；必填參數；`status`、`ability`、`template`、`routine`、`hook` 已宣告；事件名稱合法；`periodic` 有 interval；`repeat` 會停；`delay.capture` 名稱存在；`call` 參數對應；`set_state`／`set_var` 變數已宣告 |

| 出處 | `provenance` 至少一筆且格式正確；quirk 有 `text` 與合法 `policy`；`confidence` 必填 |

- `source = "kv:<Key>"` 與釘選的原作 KV 自動比對（M1 出處比對工具）。

- 跨文件引用（道具配方的零件存在於其他道具文件；英雄技能引用道具狀態）。目前只檢查格式。

## 11. 與 v2 的關係與遷移

- v2 的 `description`（寫死數字的長句）由 `text` 取代；`resources`、`targeting`、`timing` 由 `cost`、`target`、`cast` 引用 `values` 取代；`effects`（封閉詞彙）由 `behavior` 取代；`implementation = rust_handler` 的模組會在 M3 改成 IR 直譯，必要時留 hook。

## 12. 語意細則

v3.0 定案時，依試點改寫回報的問題補充。執行器（M2／M3）照這裡實作；有疑義時以這裡為準。

### 12.1 數值

- 十進位或分數字串轉 Fixed64 raw：預設四捨五入到最近的 raw（與 f32 extras 換算一致）。`rounding = "truncate"` 改成截斷，只用來重現現行 handler 的截斷行為（B01R 百分比轉比例）。
- `kv` 記原作 KV 或說明的數字；從腳本推得、原作沒有直接寫出的數字，寫在 `source_differs` 的文字裡。
- **catalog 存顯示用的數字**：compiled block 的 `ranks` 與 `raw`（v3-content-model-proposal.md §2.2）就是作者寫的數字。`pct` 的 25 存成 `"25"`、raw 25600，**不是**比例 0.25。說明、網站、UE 都直接顯示它再加 `%`。「運算式裡 pct 是比例」是 M3 IR 編譯器的換算，由它除以 100；M1 的 Rust handler 讀 extras 拿到的也是顯示數字（例如 −30），照舊自己換算。
- **分數字串和十進位一樣，只是另一種寫數字的方式，不改變單位的意思。** `pct` 一律是百分數：`"1900/101"` 是 18.81%（運算式讀到 0.1881）；`"19/101"` 是 0.188%。原作 `RandomInt(0,100) <= N` 的機率要寫 `"<(N+1)×100>/101"`。驗證器會擋下小於 1 的 `pct` 分數字串（2026-10-28 起；先前作者指南的範例寫錯，已修正，census 的 C01、B11、pilot_a、pilot_b 已改成百分數）。

### 12.2 技能與道具

- 出生自動學會：寫在 `hero.auto_learn = { "<技能 id>" }`，技能本身 `learnable = false`。
- `on_learn` 只在第一次學會時觸發；`on_upgrade` 在每次升級時觸發，包括第一次學會。
- `has_tag(x, t)`：技能的 `kind` 自動算 tag（`toggle`、`channel`、`passive`），道具自動有 `item`，`slot = "R"` 自動有 `ultimate`。`ability.is_toggle`、`is_item`、`is_ultimate`、`is_passive` 是同樣的判斷。
- 比對特定技能或道具：`is_ability(x, <技能 id>)`、`is_item(x, <道具 id>)`。名稱可以屬於其他文件。原作以名稱排除某些技能時，優先給那些技能加 tag `no_cast_trigger`。
- 需要冷卻、但沒有主動的道具（御魔護符、禦神刀）：`active = { kind = "passive", target = { type = "none" }, cost = { cooldown = ... } }`。
- `cost.charges.scope`：`instance`（預設）、`hero`（整位英雄共用）、`item_name`（同名道具共用）。`on_rank_up`：`keep_restart`（保留次數、重新計時）、`keep`、`refill`。
- `cost.cooldown_groups[].role`：`member`（預設，觸發也接收）、`trigger_only`（施放時讓同組進冷卻，自己不被同組帶進冷卻）、`receive_only`。
- 法球槽：`passive.orb_slot = { release, priority }` 宣告佔用英雄層級的法球槽；`orb_slot_free(unit, ability)` 判斷這招能不能用（槽空著或由它佔用）。`release`：`unequip`、`status_end`、`never`（原作永不釋放的 bug 照實寫，quirk 記 `fix_candidate`）。
- 道具 id：原作名稱轉小寫，去掉 `[a-z0-9_]` 以外的字元（`item_samurai's_badge` → `item_samurais_badge`）；`source_id` 保留原名。

### 12.3 狀態

- `per_source = true`：每個施加者各自一個實例（各自 refresh）；預設同一個狀態在一個單位上只有一份（`independent` 除外）。
- `reapply_if_removed = true`：被驅散或移除後，只要來源條件仍成立就立刻補回（原作每 0.1 秒檢查並重套）。
- `unique_rule`：同一個 `unique_group` 內 `max`（預設，逐屬性取最高）或 `latest`（最後套上的生效；原作同名 modifier 互相覆蓋）。
- `absorb.phase`：`post_mitigation`（預設，以減免後傷害扣盾）或 `pre_mitigation`。
- `scope = "item_instance"`：每個道具實例各自一個狀態實例；兩件同名道具就有兩份，要只取一份用 `unique_group`。
- `immune_to` 可以寫 `tag:<名稱>`，表示免疫帶這個 tag 的狀態。狀態的 `tags` 是自由字串，但以下由規則層統一使用：`slow`（緩速類）、`invisible`（隱形）、`engine_invisible`（原作引擎的 modifier_invisible，有效果只移除這一種）、`true_sight`、`cleanse_protected`（原作 `_G.EXCLUDE_MODIFIER_NAME`）。跨文件引用別人的狀態用 tag：`has_status_tag(unit, tag)`、`remove_status { tags = {...} }`。
- 狀態旗標：`true_sight`＝持有者看得到範圍內的隱形單位；`revealed`＝持有者對施加者的隊伍失去隱形（原作 modifier_truesight 掛在被看穿的人身上）；`cannot_be_magic_immune`＝不能獲得魔免（原作 `nomagic`）。
- datadriven modifier 沒寫 `IsPurgable` 時，暫定 `dispel = "basic"`；Lua modifier 沒覆寫 `IsPurgable` 時暫定 `none`。兩者都是推定，記在 quirks；M2 規則層實測後統一修正。

### 12.4 action

- `remove_status`：
  - `status`：依 id 移除，**不看** `dispel` 類別（原作 RemoveModifierByName）；
  - `dispel`：依可驅散類別移除；`all_debuffs`、`all_buffs`、`all` 不看類別；
  - `tags`、`states`：只移除帶這些 tag 或狀態旗標的；`except`、`exclude_tags`：排除；
  - `team_of_source`：施加者相對於**被驅散者**的隊伍；`min_remaining`、`min_duration`：剩餘時間、總時間門檻；`limit`：最多移除幾個（依 entity id 與套用順序）。
  - 至少要有 `status`、`dispel`、`tags`、`states` 其中之一。
- `create_illusion`：
  - `copy = { level, abilities, except_abilities, items = "same"|"fresh"|"none", statuses, hp, mana, unit_state }`。預設：等級、技能與技能等級、道具（`fresh`，新實例）都複製；狀態不複製；生命與法力等於本體目前值。
  - `outgoing`、`incoming` 的鍵是 `physical`、`magical`、`pure`、`all`，值是**增減比例**（Dota 慣例）：`outgoing.all = -0.7` 表示只造成 30% 傷害；`incoming.all = 3` 表示承受 400% 傷害。用 `pct` 數值時記得它在運算式裡是比例。
- `create_unit.overrides` 的鍵見詞彙表（`hp`、`attack_damage`、`attack_damage_max`、`level`、`ability_level`……）。
- `modify_base_stat`：改基礎三圍（白字，原作 ModifyAgility）；`stats` 的 `str`／`agi`／`int` 是額外（綠字）。
- `spend_mana`：單位自己付法力，會觸發 `on_mana_spent`；`burn_mana` 是被燒。
- `pick_item { from, where, order, slots, as }`：從背包挑一件道具，`where` 裡 `it` 是道具；挑不到時 `as` 為空，後面用 `exists(x)` 判斷。
- `give_item.item` 可以是道具 id 或運算式（`unit_state` 型別 `item_name`，例如先存 `x.name`，原實例銷毀後再以名稱新建）；`vars` 初始化新道具實例的 `item_instance` 變數。`swap_item` 交換兩個道具實例的位置，實例本身（充能、冷卻、變數）不變。
- `set_state`：`on` 預設是 `caster`（`scope = "hero"` 的變數存在 `caster_hero`）；`scope = "item_instance"` 的變數要給 `item`。
- `chance`：`counter`（`ability`、`hero`、`item_name`、`status`）是隱含的保底計數；`counter_var` 改用一個宣告的 `unit_state`（int），可以被 `set_state` 設定或清零。`scope = "hero"`、同名同型別的 `unit_state` 在不同文件裡是**同一個變數**（跨道具共用的計數，例如原作 `caster.raikiri`）。
- `teleport`：`find_clear_space`（預設 true；原作 SetAbsOrigin 寫 false）；`max_distance`：超過就停在最遠處。
- `projectile`：`where` 裡 `it` 是候選單位；`hit_priority = { "enemy", "ally" }`：同一步同時碰到時先選前者；`arm_distance`：飛行這段距離內不判定命中；`lifetime`：存活上限；`remove_on = { "owner_death" }`。
- `tether`：沒寫 `max_distance` 就不會因距離斷開；連結本身不是狀態，不能被驅散。`from` 死亡不會結束連結，到期照常執行 `on_expire`（已死的 `from` 用最後位置；完全沒有位置時當成距離上限）；`to` 死亡或被移除時連結結束，`on_expire` 與 `on_break` 都不執行。（依現行 `tether.rs`）
- `reveal`：視野屬於 `teams` 指定的隊伍，不因施加者死亡而結束，持續到 `duration`；有 `follow` 時中心每一步跟著那個單位，單位從場上移除就提早結束；只給一般視野，`true_sight` 預設 false。（依現行 `reveal_zone.rs`）
- `pull { along = <投射物> }`：沿那個投射物走過的路徑倒退回起點；`max_duration` 到了就停。
- `zone`：第一跳在 `first`（預設等於 `interval`），之後每 `interval` 一跳，`duration` 到了就結束（最後一跳在 `duration` 當下也算）。
- `delay`、`repeat`、各種回呼看到的綁定是**排程當下的值**（自動捕捉）；`capture` 只是明示。
- `damage.flags` 的 `no_source_bonuses`：傷害不套用來源的增幅、吸血等加成（原作改由 dummy 造成的傷害）。
- `create_pickup`：`killable` 可被攻擊摧毀，`on_destroyed`；`destroy_tree { tree }` 只砍一棵。

### 12.5 事件與選取

- `on_ability_executed`：技能與道具都算（Dota OnAbilityExecuted），在施法者自己的 `on_cast` **之前**觸發。只看道具用 `on_item_used`。
- `on_attacked`：被攻擊、判定時（命中或未命中）；`on_attacked_hit`：只在命中時。原作 datadriven 的 OnAttacked 依實際行為選。
- `on_order_targeted`：多個攔截者依 `priority` 由高到低執行；一旦 `cancel_cast`，其餘不再執行。`event.order.by_player` 分辨玩家命令與腳本命令。
- `prefer` 的候選和一般候選一樣受 `team`、`flags` 篩選。
- `is_visible_to(x, u)`：`u` 的隊伍看不看得到 `x`。`unit.hero`：擁有這個單位的英雄（英雄自己就是自己）。`primary_is(u, str|agi|int)`：主屬性判斷。

### 12.6 運算式

- 角度一律用度：`sin`、`cos`、`rotate`、`polar` 的參數與 `atan2`、`angle_between` 的結果。原作用弧度時，把換算寫進數值。
- 位置與向量的四則運算是逐分量計算；`位置 × 數值` 合法（照實表達原作的座標公式）。
- `select(c, a, b)` 只求值被選中的分支。

### 12.7 unit state

- `scope = "unit"`：存在這個單位上，跨死亡保留，單位移除才消失；分身有自己的一份。`scope = "hero"`：存在英雄上，跨文件同名共用（§12.4 chance）。
- `init` 是運算式，只能讀數值與規則層；狀態 `vars` 的 `init` 另外可以讀 `self`、`source`。

### 12.8 單位模板

- `acquisition_range`（索敵範圍）、`turn_rate`、`attack.attack_point`、`owner_death`（`persist`、`die`、`remove`）。
- `over_limit = "orphan_oldest"`：最舊的一隻失去存活時間與名額但留在場上（原作下忍超額的 bug）。

### 12.9 對局值

- `game.creep_wave`：目前出兵波次（原作 `_G.A_count`）；`game.creep_armor_bonus`：出兵護甲加成（原作 `_G.armor_bonus`）。兩者由遊戲模式提供，M2 之後接上。

### 12.10 v3.1 追加（M4 普查 H1～H8、I0、I1 的缺口）

- **傷害類型**：`event.damage.is_physical`、`is_magical`、`is_pure`（布林）。例如「只對物理傷害反擊」寫 `filter = "event.damage.is_physical"`；「取消施法者所有物理傷害」在 `on_deal_damage_pre` 用 `filter` 加 `modify_damage { cancel = true }`。
- **物理傷害免疫**：狀態旗標 `physical_immune`。物理傷害在減免階段（v1 §1 傷害管線第 ③ 段）直接歸零，先於所有增傷、減傷百分比；也就是說，增傷 % 對它沒有作用，魔法與純粹傷害照常。
- **跨文件共用的變數**：`scope = "hero"` 或 `scope = "unit"`，而且同名、同型別的 `unit_state`，在不同文件裡是**同一個變數**。原作的 `unit.AphoticShieldRemaining` 就是這樣共用。要私有就加技能前綴命名（`c06r_shield_left`）。共用護盾池的規則層版本由 M2 決定，屆時可以改用 StatKey 或狀態。
- **魔抗池**：StatKey `magic_resist_pool`，增減 nobu 魔抗池（上限 `rules.hero.max_magic_resistance`）；同名道具只算一次，用 `unique_group`。規則層 M2 實作。
- **回復**：
  - `hp_regen_pct`、`mana_regen_pct` 是「每秒回復最大值的百分比」；
  - `hp_regen_amp_pct`、`mana_regen_amp_pct` 是回復量的增幅百分比；
  - `base_move_speed` 覆寫基礎移速，加成照算；
  - `miss_chance_pct` 是攻擊落空機率。
- **remove_status**：
  - `only = "debuffs"|"buffs"`，可以只移除負面狀態，例如自我強驅散；
  - `exclude_source_tags`：跳過施加來源技能帶這些 tag 的狀態，例如 `{ "ultimate" }`；
  - `source_ability`：只移除某招施加的狀態；
  - `source_is = { ... }`（v3.2）：依施加來源篩選，列出的條件都要成立才移除：`has_ability`（有來源技能）、`no_ability`（沒有來源技能，例如規則層或腳本直接掛的）、`alive`（施加者還在場上）、`gone`（施加者已不存在）。
- **chance**：`mode = "prd"` 是 Dota 式偽隨機分布，p 是名目機率；預設 `independent`。`pity_after` 是另一種保底，兩者可以並用。
- **單位與狀態旗標**：
  - 單位 tag `general`（侍大將，原作 com_general_*）；
  - `melee_attack`／`ranged_attack` 強制攻擊方式，`is_ranged` 跟著反映（原作 SetAttackCapability）；
  - `flying_for_pathing` 只改尋路，不給飛行視野；
  - `block_disabled` 讓物理格擋失效。
- **說明引用其他文件的道具**：`{@item_xxx}` 可以指向別份文件的道具。建置時從 `docs/character_pipeline/items/*.lua` 取名稱；驗證器只檢查 id 格式。
- **分身**：`create_illusion.copy.status_duration = "remaining"|"original"`、`status_caster = "original"|"illusion"`。
- **routine** 加 `owner = "<技能 id>"`：可以用 `$x` 讀那招的數值、`state.x` 讀那招的 `unit_state`。
- **其他 action**：
  - `knockback.stop_on_contact`（加 `contact_radius`）：碰到單位就提早停止並執行 `on_end`；
  - `hook.callbacks = { 名稱 = { actions } }`：讓 hook 回呼資料行為；
  - `clear_state { var, on }`：清空變數；
  - `temporary_night { duration }`：全圖暫時夜晚，期間 `game.is_night` 為 true。
- **法球槽**：`orb_slot.claim = true`，學會、裝備或開啟（toggle）時就強制佔用；`orb_slot.overridable = true`，佔用中仍可以被之後佔用的其他法球覆寫（B15E）。沒有 claim 的法球只在槽空著時生效（`orb_slot_free`）。
- **到指定等級才自動學會**：寫 `hero.auto_learn`，加上技能的 `requires.hero_level`。到那個等級時自動學會，不花技能點（v2 auto_learn 的語意）。
- **引擎內建 modifier**（例如 modifier_treant_overgrowth）：一律寫成一般 status（定身＋cue），不建內建狀態表。
- **不移植的條目**：文件層 `deferred = { { source_id, reason, note, id? } }`；`reason` 可以是 `not_in_source`（原作 KV 沒有定義或整段被註解）、`old_version`、`unused`。也可以在條目本身寫 `coverage = "deferred"` 加 `deferred_reason`，這時 `text` 的 body 與 `target` 都可以省略。
- **單位模板**：`inventory_locked`（不能動背包）、`item_cast_blacklist = { "item_x" }`（不能使用的道具，B07E 國崩隊）。
- **其他**：單位屬性 `illusion_damage`（規則層的分身傷害倍率，本體為 1）；`shop.stock.first_restock`；運算式名稱 `none`（空引用，可以 `set_state { value = "none" }` 或 `x == none`）。
- **語意**：
  - `set_stacks` 的值小於等於 0 時，移除那個狀態；
  - `repeat` 省略 `interval` 時，所有次數在同一步內依序跑完；
  - `v2_only = true`（hidden，搭配 `v2_key`）：M1 遷移專用，標記沒有人讀、只為了和 v2 數字比對而保留的值，算「有人用」。M5 刪除。
  - 衍生值（`expr`）的結果先轉成九位有效數字的十進位，再換算 raw，不先捨入到 Fixed64 格點。

### 12.12 v3.3 追加（狀態對應 runtime，2026-10-29）

- 狀態欄位 `runtime_id`：現行 runtime（Rust handler 或 host）在 BuffStore 用的 buff id，讓 UE 的狀態列與 M3 的直譯器對上 v3 狀態。
  - `{caster}` 代表施法者 handle 的 `id:gen` 後綴（omb-script-abi `buff_ids`），例如 `generic_slow:spell_book:{caster}`（道具用去掉 `item_` 的遊戲 id）；`{rank}` 代表擁有者目前的 rank，例如 `a07_strongest_r{rank}:{caster}`。
  - 標準控制狀態（`stun`、`root`……）寫共用的 id。
  - 沒寫就是 runtime 沒有對應的 buff，例如只在資料行為裡的狀態。
- 編譯時帶進 catalog 的 `statuses[].runtime_id`，IR 的 `statuses[].runtime_id` 也讀它。
- 技能（與道具 `active`）欄位 `bot`：server bot 與 UE autopilot 什麼時候、對什麼施放這一招。
  - 寫法同 omoba-core 的 `BotAbilityIntent`：`{ kind = "enemy_point", radius_key = "$radius", min_targets = 1 }`。`*_key` 參數寫成 `$值名稱`，門檻值（`below_hp_per_mille`、`threat_radius`…）是策略數字，不算未命名的遊戲數值。
  - `bot = false`：bot 不施放。
  - 沒寫時由 target、cast、cost 與施放行為推導（`tools/v3_bot.lua`）。只有現行執行器表達不了、或實機驗證過的門檻，才需要手寫。
- 技能與道具欄位 `host`：行為已經是資料（`coverage` 是 expressible、needs_hook 或 pending），但 host 元件仍以固定名稱從 catalog 讀的值。
  - 寫法：`host = { component = "attack_orb", reads = { "$attack_orb_attack_speed_slow_constant" } }`。用到多個元件時寫成陣列，例如 `host = { { component = "ability_projectile", reads = { "$max_targets" } }, ... }`。
  - `component` 是 host 元件名稱（v3_vocab `HOST_COMPONENTS`，例如 attack_orb、ability_projectile、flame_trail），`reads` 是元件讀的 `$值`，驗證器把它們算成有人用。
  - 這和 `v2_only`（沒有人讀、只留給 v2 副本比對）不同；`handler.reads` 則是 coverage = rust_handler 時 Rust handler 讀的值。
  - 只是驗證用的宣告，不進 catalog；host 讀的是值本身（catalog 的 values 照常帶）。rust_handler 與 deferred 的條目不能寫 host。
  - 種類清單見 `v3_bot.lua` 的 `KINDS`。標 `proposed` 的種類（`toggle_engage`、`ally_engage`、`summon_near_enemy`、`escape`、`channel_enemy_area`）要等執行器支援，見 `docs/plans/2026-10-28-history-nobu-full-port/m6-bot-intents.md`。
  - catalog 的 `bot`：intent 的 JSON 形狀，`*_key` 換成值名稱，另加 `source`（authored／derived），以及必要時的 `proposed`、`reason`。

### 12.11 v3.2 追加（全量普查後）

- **跨文件登錄表** `docs/character_pipeline/schema/v3-shared-registry.lua`：
  - `unit_state`：跨文件共用的變數名稱與型別，例如 `aphotic_shield_remaining`、`raikiri`；
  - `status_tags`：其他文件會讀的狀態 tag；
  - `cooldown_groups`：共用冷卻組，一律命名為 `<系列>_family`，例如 `fire_family`、`wind_family`、`mountain_family`、`boots_family`。
  - `item_tags`：道具條目以 `tags = { "blink" }` 宣告的道具 tag（`modify_cooldown { item_tag = "blink" }` 讀取）；道具的 tag 一律要登錄。
  - 規則層的狀態 tag `from_ability`：凡是由非道具技能施加的狀態，規則層都會自動帶上（分身用 `copy.status_tags = { "from_ability" }` 只複製技能狀態）。
  - 單位 tag 是封閉詞彙（詞彙表的 types），例如 `boss`、`general`，不必登錄。
- **驗證器的跨文件檢查**：
  - `scope = "hero"`／`"unit"` 的 `unit_state`，名稱必須登錄在表上（型別也要相同），或以文件、條目的前綴開頭（私有變數，例如 C01 的 `c01r_noncrit`）；
  - 讀取的狀態 tag（`has_status_tag`、`remove_status` 的 `tags`／`exclude_tags`、`immune_to = tag:x`），必須由這份文件的狀態宣告，或登錄在表上；
  - `cooldown_groups[].group` 必須登錄。
  - `scope = "match"` 是全場只有一份的變數（原作全域變數，例如 B30T 的 tsum），命名規則和 hero／unit 相同。
  - 新增共用名稱時先加進登錄表，並寫 `source`。
- **新 action**：
  - `chain { from, first, jumps, radius, team, where, take_while, allow_repeat, order, actions }`：連鎖彈跳。每一串有自己的命中表，`actions` 裡的 `it` 是這一跳的目標、`jump` 是第幾跳（第一個目標是 1）；`take_while` 遇到第一個不符合的候選就整串停止（赤雷卷遇到隱形單位中斷）；
  - `impulse { who, direction, speed, decay, duration }`：可疊加、會衰減的速度衝量；
  - `redirect_motion { who, toward／direction, speed, distance }`：改變進行中的擊退、衝刺或拉扯；
  - `set_base_max_hp { to, value }`；
  - `set_time_of_day { mode = day|night, duration }`（`temporary_night` 是它的簡寫）；
  - `clear_slow_pool { of }`：只清空規則層的緩速池，狀態本身不移除。
- **選取** `take_while = 條件`：照排序走訪候選，遇到第一個不符合的就停，只留前面的。
- **偷技能**：
  - `ability_in_slot(unit, Q)`：取那一格的技能；
  - `add_ability`、`remove_ability` 的 `ability` 可以是運算式，`add_ability` 另有 `slot`、`cast_point`（覆寫前搖）、`as`；
  - `event.ability.slot_index` 是技能格位置（Q=1……F=6）。
- **分身**：
  - `create_illusion.copy.status_tags`／`status_except`：只複製帶這些 tag 的狀態，或排除某些狀態；
  - `copy.team = "caster"|"original"`：分身屬於哪一隊。預設 `caster`，所以對敵方施放時，分身屬於施法者那一隊。
- **其他**：
  - 狀態旗標 `attack_slow_immune`；
  - `modify_cooldown` 可以用 `item`（道具實例）或 `item_tag`（背包裡所有帶這個 tag 的道具），這時 `ability` 可以省略；
  - `attack.fake = true`：只觸發命中效果，不造成傷害；
  - `slow_pct` 可以是負值，表示加速。規則層合成時，負值和正值一起加總，再套用上下限。
- **召喚物追擊 AI**：
  - 單位模板 `ai = "chase_target"`，搭配 `chase = { speed, max_distance, anchor, reach_radius, retarget, give_up_after, on_reach }`。`max_distance` 是離 `anchor` 多遠就放棄追擊，`anchor` 可以是 `owner`（預設，主人）或 `spawn`（建立的位置）；`leash` 是 `max_distance` 的舊名，留著相容；`teleport_back_distance` 是離「目前目標點」多遠就瞬移回 `anchor`（原作 Exorcism 的 max_distance）；
  - `create_unit.ai_target` 指定要追的單位；
  - `on_reach` 在碰到目標時執行，裡面的 `target` 是被追的單位。原作兀鷹（A29T）、亡靈（B10W）、魂體（C16R）共用這套。
- **指令種類**：`order_is(event.order, move)`，種類清單見詞彙表。
- **語意明定**：
  - `repeat` 的 `while`、`stop_when` 在每一次執行前檢查，包括第一次（`first` 延遲之後）。`while` 不成立、或 `stop_when` 成立，就不再執行；
  - `random_point(center, min, max)` 的距離在 [min, max] 內均勻分布，方向也均勻，和 Dota `RandomVector(RandomInt(min, max))` 相同，所以越靠中心越密。要在面積上均勻分布，用 `random_point_area`；
  - `cooldown_groups[].length` 是共用冷卻的長度取誰的：
    - `own`：施放的這招自己的冷卻（預設）；
    - `group_max`、`group_min`：同組中最長或最短的冷卻；
    - `caster`：沿用施法者目前那個值；
  - `kv:` 出處：`kv:<Key>` 後面可以加空白再寫註解，比對工具只讀第一個鍵名（`kv:<Block> <Key>` 的形式除外）。較長的說明請寫在 `note`；
  - `provenance` 的路徑可以含空白（`vscripts/heroes/C21 x.lua:12`），也可以加引號（`"…":12`）。
