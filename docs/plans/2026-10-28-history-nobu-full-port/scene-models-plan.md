# 場景元件模型盤點與面數上限（工作線 C，2026-11-01）

使用者 2026-11-01 20:10 指示：用 Tripo 補齊場景缺的模型，而且面數一定要低，配備差的電腦也要跑得動。這份是盤點結果、每類的面數上限和生成順序。實際面數與點數會記在 `docs/plans/2026-10-24-omfue-month-mvp/asset-ledger.md`。

## 面數上限

Tripo 生成時一律設 face limit。上限是單件三角面數，以 UE 匯入後的實際數字為準。超過就在 Tripo 重新減面，或換更簡單的參考圖重做。

| 類別 | 上限（tris） | 理由 |
|---|---|---|
| 樹（每種） | 800 | nobu 有 1,564 棵，是 instanced；目前的 Kenney pine 只有 230 |
| 崖壁／石牆模組 | 1,500 | 305 個地形矩形，用模組拼接重複使用 |
| 石頭、植物、營地小道具 | 1,500 | 數量多，只是裝飾 |
| 守衛燈籠 | 2,000 | 對局中可能同時出現幾十個 |
| 外塔、大將塔 | 5,000 | 每張圖 42 座 |
| 兵營、商店、泉水、魔王坑 | 8,000 | 數量少 |
| 主堡 | 15,000 | 全場只有 2 座，算大型建築 |

## 順序與點數

依使用者指示，點數先給武將（10 位，每位約 45 點：生成 25、綁骨 20）。剩下的再依上表順序做場景元件（靜態單張圖每件約 25 點）。點數不夠就停，不超支。
