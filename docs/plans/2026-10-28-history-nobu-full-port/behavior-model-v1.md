# 技能行為模型 v1

omoba 自己的技能、道具、狀態 API，不追求與 Dota 相容。

- 依據：v0 草案，以及 2026-10-28 試點普查的結果（`census/`）。試點涵蓋最難的 8 位英雄共 43 筆技能與 25 個道具，找出 184 個缺口與 4 個 hook。
- 目標：原作每招技能、每個道具，都能用本模型的**資料**表達。只有本模型真的表達不了的地方，才寫 Rust hook，並且要寫明原因。
- 執行方式：Lua 寫作者資料 → 建置期編譯成 content → Rust 通用執行器執行。遊戲執行期沒有 Lua。

## 0. 分層

| 層 | 內容 | 誰維護 |
|---|---|---|
| **規則層** | 整個遊戲共用的結算規則：傷害、攻擊、緩速、魔抗、狀態抗性、治療、隱形、目標排除 | 引擎，一份；數值放 `game_rules.lua` |
| **內容層** | 技能、狀態、道具、單位模板 | 每位英雄、每個道具各自一份資料 |
| **hook** | 內容層表達不了的少數邏輯 | 個別的 Rust 函式 |
| **呈現層** | cue（特效、音效、動畫） | UE；不影響結算 |

規則層的作用：原作有很多「每一招都要遵守、但寫在全域腳本裡」的行為，例如 AMHC 的「攻擊者死了不造成傷害」、`eventfordamage` 的「魔法傷害對魔免歸零」、自訂緩速系統。這些只在規則層寫一次，**技能資料不能各自重做**。

## 1. 規則層

| 規則 | 原作依據（試點） | v1 定義 |
|---|---|---|
| 傷害管線 | AMHC Damage、`eventfordamage.lua` | 分成四段：①建立傷害（來源、歸屬、類型、旗標）→ ②**減免前事件**（可以修改）→ ③減免（護甲、魔抗、格擋、護盾吸收、免傷）→ ④**減免後事件** → 致死判定 → 擊殺歸屬。`require_source_alive` 預設依原作為 true |
| 魔免 | `eventfordamage.lua:30-32` | 魔法傷害對魔免單位為 0；「穿透魔免」只影響能不能指定與控制 |
| 魔抗 | `dummy.lua:690-700` | 英雄基礎魔抗池 30、上限 70，與裝備或技能的額外魔抗分開。數值式可以讀 `base_magic_resist`、`magic_resist` |
| 緩速 | `slow_self`、`ms_slow` | 自訂緩速通道：同類取最強或依規則合成，套用緩速抗性；最低移速與上限 700 由規則層處理 |
| 狀態抗性 | `states_res` | 縮短控制時間。個別狀態可以宣告 `status_resistance = "ignore"` |
| 治療 | 減療腳本 | 多個減療效果取最強，不疊加 |
| 隱形 | — | 隱形等級、偵測等級、破隱條件（攻擊、施法）、淡入時間 |
| 目標排除 | `_G.EXCLUDE_TARGET_NAME` | 改用單位 tag（例如 `untargetable_by_spells`），selector 預設排除 |
| 分身 | 各分身腳本 | 依傷害類型分別設定造成與承受傷害的倍率；分身是否觸發攻擊特效 |
| 偽隨機 | C01R、B11R、武尊環 | `chance { p, pity_after }`。計數器可以宣告共用範圍：同一個技能、同一位英雄、同名道具 |
| 爆擊 | C01R、武尊環 | 爆擊在攻擊前搖開始時擲骰，記錄在這一次攻擊上；多個來源取最高 |
| 光環 | 珍珠圓盤、道具光環 | 同名光環有多個來源時取最高；離開範圍後的殘留時間 `linger` |

## 2. 攻擊管線（使用者 2026-10-28 確定）

- **三個階段**：前搖 → 發出 → 後搖。
  - 近戰在發出時判定；遠程在發出時產生投射物，抵達時判定。
  - 後搖可以被移動或其他指令取消。
- **命中、未命中是判定時觸發的事件，不是階段。** 判定依閃避、致盲、必中、目標失效。
- **攻擊紀錄（attack record）**：每一次攻擊有一筆紀錄，存放這次的爆擊、出手時計入的加成、法球、是否觸發攻擊特效、觸發特效的倍率。各階段與事件都可以讀寫。
- **事件**：`on_attack_windup`、`on_attack_launch`（法球扣魔、出手時才計入的加成在這裡結算）、`on_attack_hit`、`on_attack_miss`、`on_attack_cancel`、`on_attacked`（被攻擊方）。
- **法球槽**：同一時間只有一個法球生效，優先序由資料宣告。攻擊建築時可以宣告不扣魔。
- **action `attack`**：以技能觸發一次真的攻擊。選項：是否套用法球、是否觸發攻擊特效、觸發特效的倍率、無視射程。
- **action `modify_attack`**：只改這一次攻擊。

## 3. Ability（技能與道具主動）

v0 §1 的內容，加上：

- **`tags`**：ultimate、toggle、item、channel、basic 等。給規則與其他技能判斷用，取代以名稱判斷。
- **target**：新增 `vector`（起點加方向，兩點施法）。
- **`cast.immediate`**：施放時不打斷目前的動作。
- **`cost`**：
  - `cooldown_groups`：可以同時屬於多組共用冷卻，並宣告冷卻長度取誰的；
  - 自身耗血或耗魔；
  - 可退款的時點。
- **`learnable = false`**、**`level_link = "<另一招>"`**：子技能跟著主技能的等級。
- **限時換技能**：`swap_abilities { duration, cooldown_policy }`。原技能的冷卻要凍結、繼續計時或重置，由資料宣告。
- **施法前攔截**：在下達指令階段觸發的事件 `on_order_targeted`，可以取消或轉向。例如御魔護符的格擋。
- **限次窗口**：重施放的次數與窗口時間，例如 C07 的 T2。

## 4. Status（狀態）

v0 §2 的內容，加上：

- **`stats` 運算子**：`add`、`pct`、`set_absolute`（覆寫，例如移速設為 1）、`min`、`max`；可以依持有者條件生效（`when = condition`）。
- **層數分成兩種**：`display_stacks`（只顯示）與 `value_stacks`（數值隨層數變化）。原作有很多「層數只是顯示」的情況，要能照實表達。
- **`vars`**：狀態實例上的有型別變數，例如記住原道具名、累計傷害、計次。
- **`scope`**：存在單位、持有者英雄、道具實例或永久，決定賣掉、死亡、重生時保不保留。
- **`absorb`**：吸收護盾，可以指定傷害類型、吸收量、吸收後的觸發。
- **`charges`**：次數用完就移除，例如「格擋 N 次」。
- **免疫與阻擋**：`immune_to { tags/ids }`；`block_reapply`。
- **`dispel` 篩選**：可以依施加者隊伍、剩餘時間、tag 驅散。
- **`unique_group`**：逐屬性取最高，同名光環跨來源取最高。
- **`apply_status { duration = ... }`**：施加時可以覆寫狀態的預設時間。
- **`forced_move`**：強制朝某點或某單位走，例如偽情報讓目標走回自家主堡。宣告期間哪些指令被鎖。
- **呈現與控制分開**：只為了凍住動畫的狀態（例如原作用 FROZEN 停動畫）放進 cue，不放在控制狀態。

## 5. Action（動作）

v0 §3 的內容，加上：

- **damage**：`source`（實際造成傷害的單位）、`credit`（擊殺與助攻歸屬）、`require_source_alive`、旗標。
- **projectile**：新增 `path` 型（折線，記錄經過的點）。`pull { along = path }`：沿路徑倒拉（勾鎖鐮）。
- **`dodge_projectiles { filter }`**：讓已發射的追蹤投射物失效。
- **`create_unit`**：可以覆寫模板屬性（HP、攻擊、技能等級）；完整複製選項 `copy_of = unit`（屬性、技能、狀態、道具）。
- **`create_illusion`**：依傷害類型分別設定倍率，選擇複製哪些狀態。
- **控制流**：
  - `repeat { count, interval, while/stop_when }`；
  - 可以取消的 `delay`（給一個 id）；
  - `delay` 可以捕捉當下的數值；
  - **結果綁定**：`let u = create_unit ...`，後面的 action 可以使用 `u`。
- **routine**：同一位英雄的多招技能可以共用一段 action，例如 F 強制觸發 R。
- **`issue_order`**：可以對施法者自己下令；可以下強制移動。
- **`toggle_ability { on/off }`**：強制切換開關技能。
- **經濟**：`give_gold`、`take_gold`。
- **背包**：`swap_item`、`give_item`、`remove_item`、`drop_item`、拾取物 `pickup`，以及道具實例狀態。
- **樹木**：`destroy_trees`、`regrow_trees`、`create_tree`。

## 6. Selector（選取）

v0 §4 的內容，加上：

- **起點**：`owner_of(x)`、`aura_source`、`state.<var>`（存起來的單位引用）、`landmark(team, kind)`（主堡、泉水、兵營、塔）。
- **`prefer`**：先選符合條件者，沒有才退回一般排序。例如 C07T 先打被 E 綁住的目標。
- **`nearest_to(point)`**、**`visible_to(team)`**。
- **`limit` 與 `post_filter` 分開**：原作有「魔免者佔名額但不受傷」這種結果，要能照實表達。
- **types 新增** `tree`、`item_on_ground`。
- **預設排序**：依 entity id，保證決定性。

## 7. Value 與 Condition（數值與條件）

- **數值來源**：所有玩法數值都定義在技能、狀態、道具或單位的 `values` 表，行為資料以 `$名稱` 引用，不能直接寫數字（只允許 0、1、-1 這類結構常數）。說明文字與網站也引用同一份 `values`，見 [value-single-source.md](value-single-source.md)。
- **一份運算式語言**，數值與條件共用：
  - 四則運算、比較、`and`、`or`、`not`；
  - `select(cond, a, b)`；
  - `min`、`max`、`clamp`；
  - 向量運算與三角函數；
  - 點位產生器：圓周等分點、隨機點、極座標。
- **可以讀的值**：
  - 施法者或目標屬性：新增攻速、`magic_resist`、`base_magic_resist`、對特定目標的平均攻擊力、`gold`；
  - 技能自身屬性；
  - 事件參數：`event.ability.*`、`event.attack.*`、`event.damage.*`；
  - 狀態的 `vars`、層數；
  - 對局全域值：遊戲時間、比分。
- **執行 context 明確化**：`self.unit`（觸發者）、`caster`、`caster_hero`（召喚物的主人英雄）、`attacker`、`source`。

## 8. 實體引用與狀態

- **引用**：單位、樹、道具實例、投射物、zone 都可以存進 `state` 或 `vars`，用 `alive(x)` 檢查是否還存在，引用會帶世代號。
- **unit state**：每位英雄或每個技能可以宣告有型別的變數，進 parity hash。
- **持有者層級狀態**：存在英雄身上；道具賣掉、英雄死亡後仍保留。例如累積型道具。

## 9. 單位模板

- 欄位：HP、魔力、攻擊、射程、攻擊間隔、移速、護甲、魔抗、碰撞半徑、是否阻擋尋路、賞金（金錢、經驗）、內建狀態、技能、AI 模式（`none`、`follow_owner`、`guard`、`attack_move`、`owner_controlled`）。
- 每位主人的數量上限，以及超過上限時的處理：移除最早的一隻，或拒絕施放。
- 原作 bug 照實記錄，例如「下忍超額時舊的變永生」。是否要修，依 §11 的政策決定。

## 10. Hook

- 宣告方式：`hook = { name, why }`。
- **試點的 4 個 hook，v1 能消除 3 個**：
  - C06E 偷換道具：改用背包 action 與道具實例 `vars`。
  - 勾鎖鐮：改用 path 投射物與 `pull.along`。
  - 御魔護符：改用 `on_order_targeted`。
  - 改良和弓「對指定目標的無限射程，依攻擊時序計次」：暫時保留 hook，待全量普查確認是否還有同類需求。
- 每個 hook 都要有對應的 conformance 測試。

## 11. 原作行為的還原政策（待使用者確認）

試點每一位英雄、每一組道具都發現原作 bug，而且種類很多：
- 說明文字與實際數值不符；
- 腳本函式不存在；
- 全域變數錯用；
- 跟 tick 頻率有關的結果，例如勾鎖鐮在 30Hz 下只飛得到約 360 單位；
- datadriven 的層數沒有放大屬性。

建議政策：

1. **預設照玩家在原作實際體驗到的結果做**，包含數值與 bug。說明文字改成與實際一致。
2. **腳本執行期報錯而中斷的路徑**，例如呼叫不存在的函式，照「中斷後實際發生了什麼」做，通常就是沒有效果。
3. **明顯違反設計意圖、而且影響可玩性的 bug**，例如 B22R 對隊友施放卻淨化自己、C06R 的護盾擋不住致死傷害，列入「修正候選清單」，由使用者逐條決定。
4. **跟 tick 頻率有關的行為**：我們以 60Hz 模擬，照原作的設計意圖，也就是 KV 的數值，不照 30Hz 的副作用；並記入 assumptions。
