# 全部英雄狀態表

由 `tools\lua\lua.exe scripts\hero_status.lua` 從程式與實際資料產生，不要手改；重跑就更新。

**怎麼讀**

- **批次**：`m6-waves.md` 的順序。第 0 批是規劃開始前就有的十位。舊版與 2.0 版技能組（`<英雄>_old`、`<英雄>_v20`）排在最後，順序跟本體一樣；Tripo 一欄看的是本體的模型。
- **上架**：內容目錄的英雄列不是 `test_only`、不是墓碑，且有 `source_ref`（等於 `omoba_template_ids::hero_playable`）。
- **已產生**：這位英雄的招式裡，`v3_rust.lua` 沒有 blocker 的數量。
- **Q／W／E／R／其他**：headless 對局裡這招的實際施放次數（每個座位都算）。`被動` 無法施放，沒有驗證它的效果；`**0**` 是 bot 這幾局沒有施放，不等於放不出來；`未驗證` 是這次沒有這位英雄的對局。
- **普攻**：這幾局裡沒有招式標記的傷害（`(untagged)`），有就是 ✓。這是間接證據，沒有單獨量普攻次數。
- **Tripo**：模型是 `Content/Omoba/Characters/TripoV1/<英雄>/<英雄>.uasset`；綁定要同時有 skeleton、重定向動作、列在 `moba_tripo_hero_visuals.imported`。沒有的英雄用共用人形。`.uasset` 只查存在，沒有開啟驗證。
- **演示腳本**：`record_hero_spotlight.load_package` 排得出的段數與跳過的招。**影片**：`target/spotlight/<英雄>/` 目前有的 mp4 與日期；舊影片可能已被清理，也可能早於最新內容。
- 影片只看目前的狀態，沒有判斷內容對不對。conformance 的逐招結果目前不在表內（`target/v3-conformance` 沒有結果）。
